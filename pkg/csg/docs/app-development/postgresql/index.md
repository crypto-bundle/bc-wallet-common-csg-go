# Слой данных. Работа с PostgreSQL

---
**Цель**: Определить правила работы с PostgreSQL базой данных
**Категория правил**: App Development, БД
**Краткое содержание:** Конфигурация подключения, best practices для postgresql-интеграции
---
## Введение

Данный документ содержить в себе рекомендации и правила работы с библиотекой `bc-wallet-common-lib-postres`,
входящей в базовый тулкит проекта. Так же ниже представлены примеры оформления кода для демонстрации
возможностей работы библиотеки.

### Набор инструментов

В базовый набор инструментов по написанию кода для слоя данных через взаимодейтсиве с PostgreSQL входит:
- Библиотека [bc-wallet-common-lib-postres](https://github.com/crypto-bundle/bc-wallet-common-lib-postgre)
- Библиотека [sqlx](https://github.com/jmoiron/sqlx)
- Библиотека [bc-wallet-common-lib-errors](https://github.com/crypto-bundle/bc-wallet-common-lib-errors)

## Правила

- Работа с таблицами баз данных PostgreSQL должна быть разбита на несколько пакетов и сервис-компонентом.
  _**Один пакет - один сервис-компонент - одна или несколько таблиц**_.
  Сколько таблиц обслуживает один сервис-компонент - это решение на плечах разработчика.
- Группировка таблиц в зону отвественности сервис-компонента определяется их родством друг с другом.
  А так же отдаленностью их друг от друга.
- Стараемся не использовать логгер на уровне сервис-компоента слоя данных.Если нужно для отладки - то можно,
  но после лучше убрать из зависимостей.
- Для написание кода методов-ресиверов у сервис-компонента реализующего мехнизм общения с базой данных
  обязательно использовать библиотеку `bc-wallet-common-lib-postres`.
- После написания нового SQL-запроса сделай его EXPLAIN, прежде чем отправлять этот код в git.
- SQL-запросы нужно писать так что бы их можно было использовать как в транзакционном стейтменте, так и вне его.
  Для этого все SQL-запросы необходимо выполнять внутри функции `TryWithTransaction`.
- SQL-запросы которые обязаны исполняться только внутри транзакции необходимо
  обрамлять внутри функции `MustWithTransaction`.
- Форматирование SQL-кода должно быть в соотвествии с примерами указанными в [Примеры использования](#примеры-использования).
- Избегаем выставления параметров в SQL-код через `fmt.Sprintf`, используем `sqlx`.
- Не используем `query-bulder`, стараемся обойтись базовым набором функциональности `sqlx`.
- Отсутвие данных в базе данных не является ошибкой. Если в базе данных не обнаружены данные для условий
  переданных в запросе на выборку(sql-драйвер вернул ошибку `sql.ErrNoRows`), то не возвращаем ошибку.
  Наиболее вероятно что в этом случае вам нужно `return nil, nil`, где первым параметром должен был быть
  указатель на структуру модели данных, а второй параметр - ошибка. Стоит отметить что вам не нужно каждый раз
  самим проверять равенство ошибки драйвера на `sql.ErrNoRows`,
  достаточно использовать функцию-помощник `EmptyOrError`из библиотеки `bc-wallet-common-lib-postres`.
- Ошибка `sql.ErrNoRows` не должна выходить за пределы пакета реализующий слой данных и
  сервис-компонента находящегося в нем.
- Работа с транзакционным стейтментом только через возможности библиотеки `bc-wallet-common-lib-postres`.
  Не используем возможности управлением транзакциями напрямую из `sqlx` или `sql`.
  Для выполнения SQL-запроса необходимо использовать функции:
  - `TryWithTransaction`
  - `MustWithTransaction`
- Стараемся не использовать больше 1 SQL-запроса внутри `TryWithTransaction`. По сути это означает, что
  каждая функция ресивер из сервис-компонента слоя данных используется только для одного SQL запроса.
- Для управлением транзакционным стейтментом необходимо использовать функции:
  - `BeginTxWithRollbackOnError` - рекомендуемая для 99% случаев. Стартует транзакционный стейтмент,
    и автоматически делает `rollback`, если в процессе испонения запросов произошла ошибка.
  - `BeginContextualTxStatement`
  - `CommitContextualTxStatement`
  - `RollbackContextualTxStatement`
- Не используем SQL-функции в коде генерирующие значения времени:
  - `now()`
  - `current_date`
  - `current_time`
  - `localtime`
  - `timeofday()`
  - и прочее
- Не используем в SQL-коде константу `DEFAULT` при вставке или обновлении данных в таблицах.
  Всегда передаваемые из приложения агрумента с четким значением.
