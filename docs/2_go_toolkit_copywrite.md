# Стандартный набор инструментов разработки

## Описание

В рамках проекта GreenPayment принят общий для всех приложений набор библиотек и вспомогательных приложений.
В совокупности эти приложения и библиотеки формируют общий для всех приложений набор инструментов для разработки,
он же `ToolKit`.

## Цели соглашения

Целями создания унифицированного набора инструментов является:
- Ускорение разработки приложений через шаблонизацию и повторяемость 
- Устранения фактора изобретения велосипеда
- Введение четких правил и способов создания новых приложений
- Исключения проблемы менеджмента сторонних зависимостей через инкапсуляцию их в отдельную библиотеку-обертку. 

## Правила создания новой библиотеки

### Наименование библиотек

- Имя репозитория должно быть с определенным префиксом:
  - `ca-common-lib-*` - для библиотек
  - `ca-common-migrator` - для конкретной утилиты реализующей какой либо функционал
- Имя go-модуля должно следовать рекомендациям именования модулей в Go, описанный в `CSG` - Code Style Guide.

### Правила перед разработкой
Если необходимо создать новую библиотеку важно придерживаться определенных принципов перед разработкой:
- Иметь четкое обоснование в необходимости отдельной билиотеки
- Использование данной библиотеки предлагается больше чем в одном целевом репозитории
- Для библиотеки должны быть регламентированы внешние зависимости
- Для библиотеки должен быть четко определена сфера применения
- Под новую библиотеку создается отдельный git-репозиторий

При разработке должны соблюдаться следующие правила:
- Создаваемый код должен следовать принятому `CSG` - Code Style Guide.
- Зависимости на другие сущности из внутреннего `ToolKit'a` должны удовлетворяться через соответствие 
  интерфесу определенному в репозитории библиотеки. 
  Никаких прямых импортов из `bc-wallet-common-lib-*` или `ca-common-*`.
- Для репозитория должен быть создан файл README.md с описанием цели библиотеки и примерами ее использования.
- Для репозитория должен соблюдаться `Git-Flow` описанный в `CSG` - Code Style Guide.
- Структура проекта библиотеки должна позволять импортировать только то, что необходимо целевому сервису использующую эту библиотеку.
- Для версий библиотеки должно использоваться семантическое версионирование, оно же `SemVer`, описанное в `CSG` - Code Style Guide.
- Импорт обновленной библиотеки не требует обновления других библиотек
- Написанные сервис-компоненты должны реализовывать интерфесы определенные как `ABI` библиотеки,
  иными словами - _"Реализация должна соотвествовать своим же требованиям"_. 

## Что входит в набор инструментов

### Библиотеки

| Название                           | Цель                                                                                                                                                                                  | Репозиторий                                                       |
|------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------|
| `bc-wallet-common-lib-config`      | Библиотека менеджер конфигурации приложения. Поддерживает работу конфигурацией через ENV или JSON, а так же сторонний движок секретов.                                                | https://github.com/crypto-bundle/bc-wallet-common-lib-config      |
| `bc-wallet-common-lib-tinyerrors`  | Библиотека для форматированния ошибок. Более компактная и минимальная реализация форматтера ошибок.                                                                                   | https://github.com/crypto-bundle/bc-wallet-common-lib-tinyerrors  |
| `bc-wallet-common-lib-errors`      | Библиотека для форматирования ошибок. Имеет расширенный набор форматтеров, в качестве базового используется `lib-tinyerrors`.                                                         | https://github.com/crypto-bundle/bc-wallet-common-lib-errors      |
| `bc-wallet-common-lib-logger`      | Библиотека реализующая сервис-компоненты билдеры для различных логгеров - `zap.Logger`, `slog.Logger`, `log.Logger`. Только билдеры, а не реализация логера.                          | https://github.com/crypto-bundle/bc-wallet-common-lib-logger      |
| `bc-wallet-common-lib-profiler`    | Библиотека враппер над проффилировщиком приложения, реализует кастомизацию `http-сервера` для проффилирования приложения.                                                             | https://github.com/crypto-bundle/bc-wallet-common-lib-profiler    |
| `bc-wallet-common-lib-healthcheck` | Библиотека для унификации принципов проверки здоровья приложения. Реализует `http-сервер` для снятия показаний жизни приложения и вводит правила сбора данных.                        | https://github.com/crypto-bundle/bc-wallet-common-lib-healthcheck |
| `bc-wallet-common-lib-metrics`     | Библиотека для унификации снятия телеметрии прилоежения. Реализует `http-сервер` и дает возможность его кастомизации. Так же реализует пулы данных для `prometheus` формата данных.   | https://github.com/crypto-bundle/bc-wallet-common-lib-metrics |
| `bc-wallet-common-lib-jwt`         | Библиотека враппер для работы с JWT-токенами. Реализует унифицированный принцип создания и валидации JWT-токена.                                                                      | https://github.com/crypto-bundle/bc-wallet-common-lib-jwt |
| `bc-wallet-common-lib-tracer`      | Библиотека враппер над `opentracing` тулкитом. Фактически в `lib-tracer` реализует базовый конфиг для подключения к `Jaeger` и функции обрертки для трассировки                       | https://github.com/crypto-bundle/bc-wallet-common-lib-tracer |
| `bc-wallet-common-lib-grpc`        | Библиотека реализующая единые принципы создания экземпляров `gRPC-сервера` или `gRPC-клиента`. Так же `lib-grpc` реализует некоторые дефолтные опции создания как клиента или сервера | https://github.com/crypto-bundle/bc-wallet-common-lib-grpc |
| `bc-wallet-common-lib-vault`       | Бибиотека враппер для работы с `Hashicorp Vault`. Реализует обертки над различными драйверами для подключения, а так же флоу обновления токена внутри рантайма целевого приложения.   | https://github.com/crypto-bundle/bc-wallet-common-lib-vault |
| `bc-wallet-common-lib-postres`     | Библиотека унифицирующая конфиг подключение к базе данных `PostgreSQL`.Так же `lib-postres` реализует способ работы с транзакционным стейтментом.                                     | https://github.com/crypto-bundle/bc-wallet-common-lib-postgres |
| `bc-wallet-common-lib-nats-queue`  | Библиотека унифицирующая конфиг подключение к брокеру сообщений `Nats`.Так же `lib-nats-queue` реализует сервис-компоненты для работы со всеми типа консюмеров и продюсеров.          | https://github.com/crypto-bundle/bc-wallet-common-lib-nats-queue |
| `bc-wallet-common-lib-redis`       | Библиотека унифицирующая конфиг подключение к кэширующему стораджу `Redis` или `DragonFlyDb`.                                                                                         | https://github.com/crypto-bundle/bc-wallet-common-lib-redis |


### Приложения

| Название                    | Цель                                                                                                                                                                | Репозиторий                                                 |
|-----------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------|
