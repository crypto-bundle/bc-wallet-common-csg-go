# Сборка приложения. Правила организации кода

## Введение

В данном документе описаны правила регламентирующие организацию структуры директорий и файлов
внутри репозитория содержимое которых представляет из себя описание
и скрипты сборки целевых приложени для конкретного репозитория.

Данные правила описаны для сборки приложения в **локальном окружении разработчика**, правила сборки приложений через CI/CD
описаны в других файлах документации.

Данные правила описаны для сборки бинарного исполняемого файла приложения, а так же для сборки Docker-контейнера.

## Цели

Правила регламентирующие общую файловую структуру для хранения скриптов и утилит сборки приложения решают следующую задачу:
- Ускорить работу над проектом для нового разработчика - _"быстрее соберет,значит быстрее начнет работу"_
- Предсказуемый способ сборки приложения для команды DevOps - _"быстрее поймет, быстрее внедрит в стейджинг оружения"_

## Правила

Фактически все сводится к нескольким правилам:
- Сборка бинарного исполняемого приложения должна быть описана в файле `Makefile` как отдельная цель.
  Сам `Makefile` должен быть расположен в корне директории репозитория.
- Точка входа для сборки приложения должна быть конкретная директория с `main.go` внутри директории `cmd`.
- Для целевого приложения или каждого из нескольких приложений внутри репозиотрия, должены быть написаны свои Docker-файлы.
  Например `container_controller.dockerfile` или `container_processor.dockerfile`.
- Для приложения мигратора может быть создан отдельный `Dockerfile`, если это необходимо.
  Например `container_migrator.dockerfile`.
- Артефакты сборки приложений должны сохраняться в директории `build`, 
  исключение содержимого этой директории должно быть добавлено в файл `.gitignore`.
