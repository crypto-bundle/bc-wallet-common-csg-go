# Деплоймент. Правила организации кода в репозитории

## Введение

В данном документе описаны правила регламентирующие организацию структуры директорий и файлов 
внутри репозитория содержимое которых представляет из себя описание 
деплоймента целевых приложени конкретного репозитория.

## Цели

Правила призваны решать следующие задачи:
- Ускорить доставку разработчиком какой либо фичи в стейджинг окружение -
  _"быстрее поймент деплой, быстрее напишет новйы,а значит быстрее выкатит"_
- Предсказуемый и однообразный способ деплоя приложения для команды _DevOps_ -
  _"одинаково, значит предсказуемо"_

## Правила

Для того что бы добиться поставленных целей и решить указанные выше задачи, 
необходимо соблюдать следующие правила:
- _Helm-чарты_ должны быть описаны в директории  `deploy/helm`.
- Для каждого Helm-чарта своя под-директория.
- Развертывание _Helm-чарта_ и приложение на локальном окружении 
  разработчика должно быть описано в `Makefile` как отдельная цель.
  Сам `Makefile` должен быть расположен в корне директории репозитория.
- Артефакты деплоймента через _Helm_ не должны выходить за пределы директории `deploy/helm`.
  Исключение содержимого этой директории должно быть добавлено в файл `.gitignore`.
- Отладка _Helm-чарта_ не должна выходить за пределы директории `deploy/helm/debug`.
  Имеется ввиду запуск с параметрами `--debug` и рендера Helm-файлов из шаблона в конкретный
  файл или набор файлов. Исключение содержимого директории `deploy/helm/debug` 
  должно быть добавлено в файл `.gitignore`.
