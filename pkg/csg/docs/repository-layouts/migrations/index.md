# Правила создания миграций

---
**Цель**: Регламентировать правила организации файлов и директорий для миграций
**Категория правил**: Layouts, migrations
**Краткое содержание:** Код описания схем данных для базы данных, требования к SQL-миграциям
---
## Введение

Миграции необходимо для формирования схемы базы данных в соотвествии с требованиями разработки и бизнеса.
Физически миграции представляют из себе набор `.sql` файлов выполняемых 
последовательно каким либо приложением-мигратором.

Фактически требования к файлам миграции идентичны требованиями open source мигратора `goose`.

Внутри команды GreenPayment мы используем наработки из проекта `crypto-bundle` - `bc-wallet-common-migrator`.
Репозиторий проекта - https://github.com/crypto-bundle/bc-wallet-common-migrator.

## Правила

Фактически все сводится к нескольким правилам:
- Все миграции должны находить в директории `migrations`.
- Директория `migrations` должна быть расположена на первом уровне относительно корня репозитория.
- Миграции должны успешно применяться как мигратором `goose`, так и утилитой-обреткой `bc-wallet-common-migrator`.
- Миграции не должны содержать в себе запросы созданием или изменения содержимого таблицы, только манипуляции схемой данных.
- Миграции должны поддерживать механизм отката - `rollback`.
- Миграции должны запускаться внутри транзакционного контекста, за редким исключением.
- Измение одной таблицы - один файл миграции.
- Добавление индексов на несколько разных таблиц - несколько файлов миграции.
