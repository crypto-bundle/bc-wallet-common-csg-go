## Введение

В данном документе описаны правила и рекомендации по организации кода приложения в контексте _обработки ошибок_.

Данная документация описывает как пользоваться библиотеками форматирования 
ошибок входящими в базовый тулкит проекта. Речь пойдет про:
- Принципы проверки ошибок 
- Использование библиотек:
  - https://github.com/crypto-bundle/bc-wallet-common-lib-tinyerrors
  - https://github.com/crypto-bundle/bc-wallet-common-lib-errors

## Описание форматтеров

Вышеуказанные библиотеки предоставляют следующие виды сервис-компонентом отвечающих за форматирование ошибок:
- Стандартный - `DefaultErrorFormatterSvc`. Используется если необходим минимальный 
  функциона для форматирования ошибок. Не влияет на текст ошибки.
- Именованный - `ErrorScoped`, он же `скоуп-форматтер`. Используется когда у какой-либо пакет или 
  сервис-компонент необходимо связать одним пространством имени ошибок. 
- Хранящий значение - `ValuedError`, он же `валуед-форматтер`. Используется когда внутри ошибки необходимо 
  хранить какие-либо параметры помимо текста. Это может быть:
  - Целочисленные коды
  - Текстовые данные
  - Скоуп для именнованных ошибок

Каждый из форматтеров можно использовать в двух вариантах:
- В виде сервис-компонента, который можно передавать как зависимость.
- В виде вызова статичных функций из импортированного пакета.

## Правила

Правила работы с ошибками влючают в себя следующие пункты:
- Не допускаем `shadowed error`.
- Не запираем переменную ошибку внутри зоны видимости `if` без необходимости.
- Ошибка возвращаемая из импортированного пакета или интерфейса - должна быть обернутой неким `error-formatter`.
- Для форматирования ошибок используем библиотеку `bc-wallet-common-lib-errors`.
- Не форматируй ошибку дважды - стараемся избегать ситуации re-wrap одной и той же ошибки.
  Такая ситуация может возникать например в случает использования замыкания 
  или механизма вызовов функций как колбек.
- Выбирай форматтер ошибок от потребностей:
  - Если у какого-то пакета или сервис-компонента в нем, единый 
    неймсейс ошибки, то нужно использовать `ScopedErrorFormatter`.
  - Если у ошибка возникает внутри функции-ресивера какого либо сервис-компонента, 
    то форматтер ошибки нужно использовать как зависимость удовлетворяющую интерфейсу.
  - Если ошибка возникает в обособленной функции, то можно использовать форматирование ошибки
    через вызов библиотечной(`bc-wallet-common-lib-errors`) функции из пакета `errformatter`.
