# Конфигурация приложения. Правила написания кода

---
**Цель**: Определить механизм конфигурирования приложения из разных источников
**Категория правил**: App Development, config
**Краткое содержание:** Обработка env переменных, json/jsonc/yaml конфигов, работа с секретами
---
## Введение

В данном документе описаны правила и рекомендации по написанию кода в контексте _конфигурации приложения_.
Под термином `конфигурации приложения` подразумевается набор Go-структур и сервис-компонентов отвечающих за
обработку конфигурационных параметров входящих в приложение.

Про источники конфигурационных параметров описано в документе [Конфигурационные файлы](./3_go_repository_layouts_config_files.md).
Кратко можно сказать что конфигурационные параметры могут поступать из:
- Переменных окружения.
- JSON-файлов.
- YAML-файлов.
- Сервиса хранения секретов _HashiCorp Vault_.

## Правила
 
- Для работы с конфигурацией приложения используе библиотеку [bc-wallet-common-lib-config](https://github.com/crypto-bundle/bc-wallet-common-lib-config).
- Конфигурации инфраструктурных сущностей(базы данных, брокеры очередей, сервис менеджмента секретов) необходимо 
  подключать из соотвествующих библиотек. Продробнее описано в документе [Тулкит](./2_go_toolkit.md).
- Все Go-структуры конфигурации приложения должны быть собраны в одну через использования механизма `embedding`.
- Любая структура отвественная за конфигурацию приложения должна быть написана с возможностью передачи как зависимость
  реализующая некий интерфейс.
- Получение каких-либо данных из конфига должно быть написано через использование соотвествующих `Get` методов.
  Обращение к конкретным полям структуры недопустимо.
- Если сервис-компоненту конфигурации необходимо сделать некоторые манипуляции прежде чем быть готовым к работе, 
  необходимо использовать специальные методы-ресиверы:
  - `Prepare() error` - метод подготовки сервис-компонента к работе.
  - `PrepareWith(dependenciesCfgSvcList ...interface{}) error` - метод подготовки сервис-компонента с использованием каких-либо
    зависимых сервис-компонентов.
- В имена методов-ресиверов должно включаться предметная область конфига. 

  Так как каждая структура реализующая сервис-компонет конфигурации для какой-либо части приложения, подлючается
  через `embedding` механизм - то наименование методов-ресиверов в структуре должно быть сформированно 
  определенным образом. Речь идет про проблему пересечения имен методов-ресиверов нескольких сервис-компоненто,
  они одинаковые и конфликтуют друг с другом при включении нескольких структур в одну.
  Например для сервис-компонента конфигурации для подключения к брокеру сообщений Nats имеет в себе методы-ресиверы:
  - `GetNatsUser() string`
  - `GetNatsPassword() string`
  - `GetNatsConnectionRetryCount() uint16`
  - `GetNatsConnectionRetryTimeout() time.Time`
